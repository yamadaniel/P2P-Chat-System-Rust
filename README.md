# LynQ
P2Pを使用したチャットアプリ

## バージョン
0.2.0(Beta)
2026/10/22 リリース

## 使用言語
- Rust(Tauri)
- HTML
- CSS
- JavaScript

## 使用技術
- PostgreSQL
- iroh
- Docker

## 概要
チャットの際に中央サーバーを経由せずにP2P(Peer-to-Peer)で通信を行うシステム

中央サーバーは以下の際に利用される
- 新規登録
- ログイン
- ユーザー検索
- オンライン表示

それら以外で中央サーバーは使わない

## 目的
- P2P通信を利用した中央サーバーに依存しないサービスの作成
- メッセージ本文はサーバーに保存されず、中継される場合も暗号化されたまま
- 最悪の場合、中央サーバーがダウンしてもチャットを行うことはできる

## 現状の疑問・課題
- NAT越え（ローカル内では検証済み） → P2Pで繋がらない場合はリレー経由になる
- 本当に中央サーバー無しでも通信が可能なのか → 相手の送信先IDを知っていれば可能

## 現状の想定
PC-Aで登録 -> 中央サーバーに情報を送信

PC-BからユーザーIDを検索 -> 中央サーバーでの処理

PC-AとPC-Bでチャット -> P2P通信でサーバーを介さない

オンライン状態の確認は現状Issue#2にある

## 中央サーバーについて
中央サーバーにおいては1台にまとめると可用性や本番で落ちた場合に問題があるため2台構成にする。

オンプレ環境がmain、 クラウド環境をsubにすることで可用性、信頼性を向上させる。

subはmainのDBを複製する。それに伴いsubを読み取り専用にすることでDB統合の手間を省く。
